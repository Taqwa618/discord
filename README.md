# 🤖 Discord-бот (утилиты, модерация, развлечения, экономика)

Исправленная версия бота на **Python 3.8+ / discord.py 2.3+**, готовая к
заливке на GitHub и запуску на хостинге типа **BotHost** (деплой из репозитория).

---

## 1. Что умеет бот

| Категория | Команды |
|---|---|
| 🔧 Общие | `!ping`, `!hello`, `!time`, `!commands` (справка) |
| 🎲 Развлечения | `!coin`, `!roll [макс]`, `!joke`, `!cat`, `!dog`, `!meme`, `!rps <камень\|ножницы\|бумага>`, `!8ball <вопрос>` |
| 🛠 Модерация | `!clear <1-100>`, `!kick <участник> [причина]`, `!ban <участник> [причина]`, `!unban <ID>`, `!mute <участник> <минуты> [причина]`, `!unmute <участник>` |
| 👤 Информация | `!userinfo [@участник]` |
| 💰 Экономика | `!balance`, `!daily`, `!work`, `!shop`, `!buy <номер>` |

## 2. Структура проекта

| Файл | Назначение |
|---|---|
| `main.py` | Весь код бота |
| `requirements.txt` | Зависимости — хостинг ставит их автоматически |
| `.env.example` | Шаблон настроек (скопировать в `.env` для локального запуска) |
| `.gitignore` | Не даёт случайно залить `.env` и базу на GitHub |
| `economy.db` | База SQLite — создаётся автоматически при первом запуске |

> ⚠️ `main.py` и `requirements.txt` должны лежать **в корне репозитория GitHub**.
> Если сервис хостинга просит конкретное имя главного файла — укажите `main.py`.

## 3. Подготовка бота в Discord (обязательно!)

1. Откройте <https://discord.com/developers/applications> → **New Application**.
2. Вкладка **Bot**:
   - нажмите **Reset Token** и скопируйте токен (показывается один раз);
   - включите два переключателя:
     - ✅ **SERVER MEMBERS INTENT**
     - ✅ **MESSAGE CONTENT INTENT**
   - **Без них бот не запустится** (ошибка `PrivilegedIntentsRequired`).
3. Вкладка **OAuth2 → URL Generator**: отметьте `bot`, права:
   `Send Messages`, `Manage Messages`, `Kick Members`, `Ban Members`,
   `Moderate Members`, `Manage Roles`. Откройте ссылку и добавьте бота на сервер.

---

## 4. Загрузка на GitHub

1. Создайте репозиторий (например, `discord-bot`), можно **Private**.
2. Загрузите в корень репозитория: `main.py`, `requirements.txt`, `.gitignore`,
   `.env.example`, `README.md`.
3. **Не загружайте** файл `.env` и `economy.db` — они в `.gitignore`,
   токен в репозитории хранить нельзя.

---

## 5. Запуск на хостинге (BotHost и подобные)

1. Зарегистрируйтесь на хостинге и создайте проект/бота.
2. Выберите деплой **из GitHub** и укажите ваш репозиторий (при Private-репо
   хостинги обычно дают токен доступа или «подключить аккаунт GitHub»).
3. Укажите настройки запуска (названия пунктов могут немного отличаться):
   - **Main file / Start file**: `main.py`
   - **Requirements file**: `requirements.txt`
   - **Python version**: 3.10 или новее (подойдёт и 3.8+)
4. В разделе **переменных окружения** (Environment variables) добавьте:

   | Имя | Значение |
   |---|---|
   | `DISCORD_TOKEN` | ваш токен бота |
   | `PREFIX` | `!` (по желанию) |

5. Запустите проект. В логах должно появиться:
   `✅ Бот ... запущен!`

### Важно про базу данных

Бот хранит экономику в файле `economy.db`. На многих бесплатных/простых
хостингах файловая система **сбрасывается при перезапуске** — тогда балансы
обнулятся. Решения:
- проверить, есть ли у хостинга «persistent storage» и включить его;
- или перевести хранение на внешний сервис (например, бесплатный план
  [Supabase](https://supabase.com)/PostgreSQL) — это отдельная доработка.

## 7. Что было исправлено в коде

1. **Сессия aiohttp** больше не закрывается в `on_disconnect` (после любого
   переподключения команды `!cat/!dog/!meme` падали). Теперь сессия создаётся
   один раз в `setup_hook` и закрывается в `close()`.
2. **Убран `bot.tree.sync()`** — в боте нет слеш-команд, синхронизация была
   бессмысленной и тормозила запуск.
3. **`init_db()` перенесён в `setup_hook`** — `on_ready` может срабатывать
   многократно, а база инициализируется один раз.
4. **Обработка `CommandNotFound`** — неизвестные команды больше не вызывают
   «❌ Ошибка: ...» в чат.
5. **Добавлена команда `!commands`** — текст ошибки раньше советовал команду,
   которой не существовало.
6. **Защита в `!mute`** — раньше можно было замьютить самого себя.
7. **Обработка `discord.Forbidden`** в `!unban`, `!buy` — понятные сообщения
   вместо traceback, если у бота не хватает прав.
8. **`!buy`: роль выдаётся до списания монет** — при сбое выдачи деньги не
   пропадают; проверка «роль уже есть» не создаёт лишнюю роль.
9. **Токен**: поддержаны и переменные окружения (хостинг), и файл `.env`
   (локальный запуск) через `python-dotenv`.
10. **Трассировка ошибок** печатается в консоль/логи — на хостинге теперь
    видно причину сбоя.
11. **`requirements.txt` зафиксирован** на discord.py ≥ 2.3.2 — синтаксис
    `member.timeout(timedelta)` работает только на версии 2.2+.
12. Мелочи: валидация срока мьюта (до 28 дней), `!userinfo` показывает дату
    входа на сервер, префикс задаётся переменной `PREFIX`.

## 8. Частые проблемы

| Проблема | Решение |
|---|---|
| `PrivilegedIntentsRequired` | Включите оба интента в Developer Portal (раздел 3) |
| Бот в сети, но не отвечает | Проверьте префикс: команды начинаются с `!` (или своего `PREFIX`) |
| `Improper token` / бот офлайн | Токен неверен или сброшен — получите новый и обновите переменную `DISCORD_TOKEN` |
| Модерация не работает | У бота нет прав/его роль слишком низкая в списке ролей сервера |
| Балансы обнуляются после рестарта | Хостинг сбрасывает файлы — см. «Важно про базу данных» |
